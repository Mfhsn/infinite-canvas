# 画布图片/视频生成积分预估接入计划

状态：已执行并完成验证（2026-07-27）  
文档依据：[积分预估（不扣费）](https://s.apifox.cn/ac4a0053-9e00-4028-a517-f4f343a7c43a/493097359e0)，页面更新时间 2026-07-27 08:27:39。

## 需求摘要

- 画布图片、视频节点的生成按钮不再因为本地静态价格未配置而固定显示 `0`。
- 使用平台的 `POST /api/v1/projects/calculate-points` 接口，根据节点当前实际模型和生成参数动态预估积分。
- 支持以下内置模型，并确保请求中的 `req_key` 是去掉渠道前缀后的原始模型 ID：
  - `doubao-seedream-4.5`
  - `doubao-seedream-5-0-260128`
  - `doubao-seedance-1-5-pro-251215`
  - `doubao-seedance-2-0-260128`
- 本次只覆盖文档和需求明确支持预估的图片、视频节点；文本、音频节点保持现状，不伪造价格。
- 预估接口只计算、不扣费。图片/视频生成任务接口没有 `points` 字段，因此不会向任务请求体添加未定义字段；积分将绑定到节点生成按钮的预估展示，实际扣费仍由平台任务接口负责。
- 积分预估是图片、视频生成的强制前置门禁：预估失败或返回 `points: null` 时不得发送真实生成请求，界面显示“重试”；重试成功后才自动继续本次生成。

## 文档结论

接口：

```http
POST /api/v1/projects/calculate-points
Authorization: Bearer <JWT>
Content-Type: application/json
```

成功响应：

```json
{
  "code": 0,
  "message": "string",
  "data": {
    "points": 123
  }
}
```

- `req_key` 是唯一必填字段，定义为模型标识。
- `platform_id` 用于平台价格映射。
- 图片计费字段包括 `count`、`ref_image_count`、`width`、`height`；文档中的 `image_quality` 仅接受 `low/medium/high`，与本项目的 `2k/4k` 不同。
- 视频计费字段包括 `count`、`duration`、`audio_flag`、`has_input`。
- `data.points = null` 表示参数非法或平台缺少价格配置。
- HTTP `422` 表示请求字段校验失败。
- 文档未公开四个模型在服务端对应的计费类型和价格公式，客户端不硬编码价格或计费类型，由平台按精确 `req_key` 决定。

## 参数映射

### 图片节点

| 预估字段 | 取值规则 |
| --- | --- |
| `req_key` | `modelOptionName(config.model)`，必须得到两个 Seedream 原始 ID 之一 |
| `platform_id` | 通过 `resolveModelRequestConfig` 得到当前模型渠道的实际 `platformId` |
| `count` | 节点本次实际生成张数，限制规则与生成链路一致 |
| `ref_image_count` | 本次实际使用的参考图数量；文生图为 `0`，图生图包含源图片和连接的参考图 |
| `image_quality` | 将画布分辨率映射为积分接口档位：`2k -> medium`、`4k -> high` |
| `size` | 使用实际宽高生成 backend 风格的 `宽x高` 字符串 |
| `width` / `height` | 复用 `resolveDreamImageDimensions(size, quality)`，将比例与 `2k/4k` 转为生成接口实际使用的像素宽高 |

图片预估不直接传非法的 `image_quality: "2k"/"4k"`，而是映射为 `medium/high`；同时传实际像素组成的 `size` 以及 `width/height`，兼容文档描述的 backend 与 backend_v2 两种图片计价风格，不把比例值如 `1:1` 错传为 `size`。

### 视频节点

| 预估字段 | 取值规则 |
| --- | --- |
| `req_key` | `modelOptionName(config.model)`，必须得到两个 Seedance 原始 ID 之一 |
| `platform_id` | 通过 `resolveModelRequestConfig` 得到当前模型渠道的实际 `platformId` |
| `count` | 当前视频节点一次生成一个结果，固定为 `1` |
| `duration` | 复用 Seedance 时长归一化逻辑，传本次实际生成秒数 |
| `audio_flag` | 由节点“生成音频”开关的实际布尔值生成 |
| `has_input` | 本次是否包含图片或视频输入；首尾帧模式为 `true`，2.0 全能参考按实际图片/视频引用判断，单独的音频引用不冒充图/视频输入 |

视频模式 `start-end2video` / `reference2video` 不属于预估接口字段，不额外传入。

## 验收标准

1. 选择任一内置 Seedream/Seedance 模型后，节点生成按钮不再因本地默认值显示虚假的 `0`。
2. 渠道模型值如 `dream-default::doubao-seedream-4.5` 发送时必须变为 `doubao-seedream-4.5`；其余三个模型同理。
3. 图片切换 `2k/4k`、比例、张数或参考图后，请求中的宽高、数量、参考图数与实际生成配置一致，积分自动刷新。
4. 视频切换模型、时长、音频开关、首尾帧或全能参考后，请求中的 `duration`、`audio_flag`、`has_input` 与实际生成配置一致。
5. 平台返回 `points: null`、业务错误、HTTP `422` 或网络失败时，界面不得显示伪造的 `0`，并必须显示“重试”。
6. 平台明确返回 `points: 0` 时按真实结果显示 `0`，不将合法免费配置误报为异常。
7. 预估失败期间，`dream_image`、`dream_video`、参考素材上传和任务轮询请求调用次数均为 `0`。
8. 点击“重试”后若预估仍失败，继续停留在重试状态；一旦当前参数预估成功，自动且仅提交一次真实生成请求。
9. 用户在重试期间修改任一计费参数后，旧预估不得放行生成，必须使用新参数重新预估。
10. 现有图片和视频任务请求体不增加文档未定义的 `points` 字段，生成、上传参考素材、轮询和节点重试逻辑不回归。
11. `bun test tests/dream-points.test.ts tests/dream-api.test.ts`、`bun run i18n:check`、`bun run build` 全部通过。

## 风险与处理

- **模型计费类型未公开**：客户端只传精确模型 ID 和真实参数，由平台配置决定；不复制服务端价格表。
- **批量图片的费用口径**：优先使用接口的 `count` 字段传本次总张数，与节点总请求量一致；测试固定此映射。
- **预估与最终扣费可能存在差异**：界面应使用“预估”语义；最终扣费和余额校验以平台任务接口为准。
- **参数快速切换导致旧结果回写**：用完整查询键和 Query 的请求生命周期隔离不同参数结果。
- **预估成功后重复提交**：用单次消费的生成意图和请求锁保证自动继续只执行一次；重复点击“重试”时复用同一个进行中的预估请求。
- **集成模式认证**：沿用现有服务端 Dream 代理注入外部 token，避免浏览器直接持有或记录 JWT。

## 已确认决策

- 预估接口超时、报错或返回 `points: null` 时，真实生成请求必须被阻止。
- 界面显示“重试”；每次重试只调用预估接口。
- 当前参数预估成功后，自动继续原生成动作，不要求用户再次点击“生成”。
- 参数变化会作废旧预估和旧生成意图，避免报价与请求参数不一致。
